Protocols

DILR in the exam (and every mock)
  1. Scan, 5 minutes max. For each set: FATE ticks on paper, count unknowns against relations, read the question stems. Unsure? Try to fix one fact in 90 seconds.
  2. Order: sets with a forced starting point first, long-but-determined sets next, open-ended sets last.
  3. Limits: 13 minutes per set, 3 minutes per question.
  4. While solving: write every comparison as an equation, check totals immediately, never overwrite a cell, box finished scenarios.
  5. After placing what’s forced, name the open choices. Test each against the most demanding condition.
  6. Before answering: tick off every condition, and check your answers against each other.
  7. TITA: always enter an answer. MCQ: only when decided or checkable.
When you panic: “too many possibilities”
  1. Stop. Write every option on paper, side by side.
  2. Find one condition you haven’t used yet.
  3. Test each option against it, one line each. Strike out what fails.
  4. If none fail, keep them all and move on. Open options are allowed.
  5. Three minutes with nothing fixed: take what you can and leave the set.
VARC in the exam
  1. RCs first, then TITAs. Skip MCQ-type VA.
  2. Paraphrase each paragraph in one plain line as you read.
  3. For each answer, go back to the line that decides it before choosing.
  4. TITAs: paraphrase each sentence, then link by what each refers back to.
QA in the exam
  1. 3-minute scan: mark in-pool questions (arithmetic, algebra, progressions, and anything whose tools are in-pool).
  2. 4-minute cap per question. Stuck? Mark it and move.
  3. Use the options: plug in, estimate, check plausibility.
  4. Last 2–3 minutes: check signs, zeros and units on answered questions.
Mock analysis checklist
  1. VARC: deciding line + leak tag for every wrong answer.
  2. DILR: scan ranking vs result; every error tagged (selection, reading, method, calculation, knowledge, time sink); one “When X, do Y” line per new mistake.
  3. QA: every question tagged (skipped on reading, abandoned, never reached, wrong); wrong ones logged in Errors.
  4. Log the mock in The Desk → Mocks.
  5. One thing to do differently next mock.
